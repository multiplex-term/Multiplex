NEW SINCE 1.3.0
• MARKDOWN IMAGES SHOW ON A PRESS — in a rendered README the ⟨image: …⟩ placeholder is now a link. Press it and the picture appears right there in the document, sized to the text column; press the caption again to put it away, or tap the picture to open it full-screen with zoom. An image hosted on the web goes through the usual link confirmation instead. Nothing is fetched until you press.
• TMUX + MOSH FIXES — TMUX split shortcuts no longer type `%` on iPad, and File Viewer starts in the current tmux or herdr pane directory.
• SELECT BLOCK STAYS WHERE YOU PRESSED — the SELECT / SELECT ALL / PASTE block and the SELECT TEXT bar could drift up (by roughly a keyboard height, or clean off the screen) on mosh tabs and in scrolled-back terminals. Two placement bugs fixed; both bars now anchor to the visible screen beside your press or selection.
• MOSH TABS NO LONGER GROW A JUNK SCROLL AREA — mosh syncs one live screen (its protocol has no scrollback), but the app was archiving stale frames above it on every keyboard show/hide, breaking the herdr layout into stacked duplicates. Mosh tabs now hold exactly the live screen, like mosh itself.
• SELECT TEXT WITH A SECOND CLIENT ATTACHED — with another differently sized client on the same session (say a laptop `herdr attach` beside your phone), tmux and herdr resize their shared screen to whoever acted last. Select Text used to measure the pane mid-move and could highlight the wrong region; it now waits for the geometry to settle before clamping.
• RESTORE PURCHASES FIXED ON TESTFLIGHT — TestFlight's App Store backend often rejects the restore sync (the `SKInternalErrorDomain error 14` some of you reported). Restore now double-checks your owned purchases directly when that happens, and the error message names something you can act on instead of a raw error code.
• OPEN FILE FROM SHORTCUTS — the new Open File action takes a host, remote file path, and optional line number, then opens that location read-only in a ▤ File Viewer tab. Bare names and relative paths start from the host's first configured working directory, or home when none is configured.
