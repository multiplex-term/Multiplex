CTRL QUICK COMBOS — press CTRL, get C / B

Pressing the rail's CTRL key (or the visionOS cluster's) now raises a
one-line C / B strip over the key while the latch is held: one tap sends
Ctrl+C (interrupt) or Ctrl+B (the tmux prefix) without summoning the
keyboard. Unlatching CTRL, typing any key, or tapping a combo puts it
away.

Worth checking:
- Press CTRL at a shell prompt, tap C: the line aborts with ^C and the
  CTRL latch releases. B likewise (B then a key drives tmux).
- Mash CTRL quickly: the strip must appear/disappear in step with the
  latch every time, never get stuck or skip a beat.
- With an agent running (helper chips above the rail), the strip must sit
  ON TOP of the chip row, tappable, not hidden behind it.
- Latch CTRL and type c on the keyboard instead: same ^C, strip goes away.
- iPad/iPhone: the strip is square chassis (no rounded popover); Vision
  Pro shows a small glass popover over the ornament's CTRL key.

IPHONE LOCKED RETURN — keep RET on the rail with the keyboard closed

Locking the software keyboard on iPhone now adds RET immediately after the
arrow keys, so the rail can still submit a command without bringing the
keyboard back. iPhone Air keeps RET, the padlock, and TMUX together in the
bottom rail; narrower phones move TMUX to its dedicated top-right button
while locked. Unlocking restores the previous compact rail.

Worth checking:
- iPhone Air: hold the keyboard key. RET should appear between the right
  arrow and padlock, with TMUX still at the bottom and no clipping.
- Type a command with a hardware keyboard or rail controls, then press RET:
  it must send Return while the software keyboard stays locked closed.
- On a narrower iPhone, lock and confirm RET stays below while TMUX appears
  at top-right; unlock and confirm TMUX returns below with no duplicate.
- iPad is unchanged: RET remains visible whether keyboard lock is on or off.

LOCKED DICTATION — use the mic with the software keyboard closed

The top-right KEYBOARD LOCKED tip now includes a microphone button. It uses
Multiplex's existing Dictation path, so an iPhone can keep the software
keyboard locked and still dictate terminal input without a physical keyboard.

Worth checking:
- On an iPhone without a physical keyboard, hold the bottom keyboard key.
  Confirm the locked tip shows a mic at top-right and the bottom key remains
  a padlock.
- Tap the mic. After permissions, LISTENING should replace the locked tip;
  STOP types the final one-line transcript but does not press Return, while
  CANCEL types nothing.
- During the permission prompts, the mic should latch immediately; tapping it
  again must cancel the pending attempt.
- After Dictation ends, the KEYBOARD LOCKED tip and mic should return. Tap the
  bottom padlock and confirm both disappear as the keyboard opens.

FILE VIEWER SELECTION — select and copy like a document

Code files and git diffs in the File Viewer (+ TAB ▸ File Viewer, or
long-press a file path in a pane) are now one continuous selectable
surface: press and drag across as many lines as you want, then Copy.
Line numbers and diff gutters never come along — code copies as plain
code, and a diff copies as a real unified diff with +/- prefixes and
@@ headers you can paste into a review or apply.

Worth checking:
- Open a source file, long-press and drag a selection across several
  lines, Copy, paste somewhere: no line numbers in the pasted text.
- Open a file at a line (long-press a path:12-style reference): the line
  should land centered with an amber wash, numbered in amber.
- Open DIFF (or the tree's ± counts for the repo-wide diff), select a
  few rows across a hunk header, Copy: pasted text reads as a unified
  diff (+/-/space prefixes, @@ header), without the old/new numbers.
- Rendered Markdown keeps its layout (per-paragraph selection), and a new
  SELECT chip in the bottom rail swaps in the raw source for cross-line
  selection — DONE returns to the rendered page.
- Scroll a big file while a change lands host-side (the 5 s watch): the
  view must not jump back to the top.
